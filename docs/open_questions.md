# Open questions

Decisions taken without the owner, cheap to undo. Each: the question, what was chosen, how to undo.

| # | Question | Chosen | Undo |
|---|---|---|---|
| 1 | Runtime depth limit | Decided by the owner (2026-11-06): the Rust model, bounded by stack size (`--stack`). Compiled code relies on Wasmtime's stack trap; the interpreter counts calls (P3c). Was: a budget of 3_000 nested expressions | A fixed call count in both, as Python's recursion limit |
| 2 | Parser nesting limit | 64, so debug builds do not overflow | Raise the constant |
| 3 | How `None`, `Ok`, `Err` get their type parameters | Expected-type passing from annotations, parameters, fields, returns and branches; no unification | Add inference later; it only accepts more programs |
| 4 | Which capability uses are allowed | Only a parameter name as a method receiver or whole call argument; everything else, including `if` branches yielding a capability, is rejected | Relax later; it only accepts more programs |
| 5 | `main` return type (rule 3) | Any type; `kio run` prints it. A `Result::Err` from `main` exits 1 (`outcome.failed` in caps.wit) | Restrict `main` to `()` or `Result<(), E>` with one check in `signature` |
| 6 | Binding a name `None`, `Some`, `Ok` or `Err` | Rejected for parameters and locals, so those names always mean the constructors | Allow shadowing later |
| 7 | How a helper's capability maps to a grant | `Value::Cap(name of the main parameter)`, passed as an ordinary value | Replace with a handle index when `guest` maps names to WIT handles |
| 8 | Host result checking in `lang` | Full: every capability call result is checked against the method's declared type (`Program::fits`), else `RunErr`. Shallow checking let a lying host panic `run`, found by adversarial review | Keep; WIT bindings in `guest` add a second check |
| 9 | Capability table source | Generated from caps.wit by `tools/capgen` into `lang/src/caps_gen.rs`; CI fails on drift | Resolved |
| 10 | Temporary runner and real directories | Runner grants none; real `--dir` waits for the host with cap-std | Add a cap-std-backed `Caps` to the runner |
| 11 | Interpreter stack as features grow | `#[inline(never)]` and small helpers keep eval frames small. Measured at P3c's 1_000-call limit: natively up to 2 MB in release and 9 MB in debug (tests run on 16 MB); in a release guest on the default 2 MB `--stack`, 1_141 calls through loops and 3_271 plain ones fit. G4 set `--stack` at 2 MB | Re-measure when features grow; the VM's case is speed (web W10) |
| 12 | `main`'s value across the WIT boundary | Printed text in `run`'s result; the host only prints it | Add a typed export later; existing hosts keep working |
| 13 | Grant handles in `run` | `own<dir>` and `own<http>` in the grant records, because wit-bindgen 0.63 generates non-compiling code for `borrow` inside a list of records. Safety is unchanged: only the host mints handles and every call is checked | Switch back to `borrow` once wit-bindgen is fixed |
| 14 | How the host gets the guest bytes | `host/build.rs` builds the guest into `target/guest` and embeds it, so one `cargo build` gives a self-contained `kio` | Build the guest as a separate CI step and load the file at runtime |
| 15 | WASI imported by Rust std in the guest | Linked with nothing granted: no preopens, env, args, network or stdio; frozen clocks and a fixed random seed so runs are deterministic. kio code cannot reach WASI | Build the guest without std WASI imports (no_std or a custom target) to remove them entirely |
| 16 | A grant that matches no `main` parameter | Error before any code runs, like a missing grant, so an operator typo (`--dir inptu=..`) is caught | Allow and ignore unused grants |
| 17 | `Dir.create` on an existing file | Fails with `denied`: no overwrites | Add an explicit `write` method later, or a grant flag allowing overwrite |
| 18 | `Dir.create` when the write fails partway | The host removes the file it just created, so a retry works. A crash mid-write can still leave a partial file | Write a temp file, then `hard_link` it into place (refuses to overwrite) and remove the temp |
| 19 | What the wall clock bounds | Guest execution and every `Dir` and `Http` call: each runs on a worker thread and the host waits only until the deadline (H5). A timed-out worker keeps running detached; at most 64 live at once process-wide (W8), after which host calls fail as timeouts. Granted dirs serve regular files only (W11b): a FIFO or device is `denied` at open, so it cannot block a worker; a hung network filesystem still can. A slow `create` may still write its file, confined and charged, after the run stops | Cancellable I/O, so timed-out work stops |
| 20 | Bounds on host work driven by guest input (H6 review) | Paths over 4,096 bytes are `invalid-path` before any allocation; at most 100 diagnostics plus a count; timeouts cap at a year. The review found no confinement, handle or guest-limit bypass in 35 attacks | Raise the caps if real programs need it |
| 21 | `Http` request shape | The host builds the URL from the grant and the guest supplies only a path starting with one `/`, with no control characters, spaces, `\` or `#`; GET only, no custom headers, redirects not followed (N2), proxy variables ignored | Add methods and headers when kio-web needs them |
| 22 | DNS pinning hook | `ureq::unversioned::resolver::Resolver`, which ureq does not cover by semver; a ureq upgrade may need changes. Named hosts resolving only to private addresses cannot be granted; use an IP literal | Pin ureq's minor version, or resolve ourselves and connect by address |
| 23 | `Outgoing.send` refusals | An invalid send (bad status, CR or LF in a header, header lists of unequal length) is not recorded, so the program may retry; a second valid send is `already-sent`. Every attempt counts as a call and charges its body to `--io` | Treat any send, valid or not, as final |
| 24 | Module shape | Flat: one file per module, `mod` only in the root file, always qualified (`web::f`), no `use`. Modules may use each other's `pub` items (cycles allowed), not the root's | Nested modules and `use` later; both only accept more programs. To forbid sibling use, restore the module check in `Scope::member` |
| 25 | Telling a module from a type in `a::b` | By case: a lowercase name is a module, so `struct` and `enum` names must start uppercase (checked, with a rename hint) | Resolve by declared names instead of case |
| 26 | Private types in public signatures | Allowed: a `pub fn` may return a private struct, and callers can read its fields. Module privacy organizes code; capabilities are protected by rule 1, not by `pub` | Reject private types in `pub` signatures, as Rust does |
| 27 | Audit log guarantees | One line per call, written after the work and before the host function returns: a crash inside a host call can lose that line. The report check runs always, not only with `--audit`. `program_hash` is SHA-256 over each file's name and source (W13b) | Write a "begin" line before each call |
| 28 | Per-request instance pool | 64 instances, 64 MB memory each (reserved address space, touched only as used); a full pool fails the request, which W7b answers with 503 | Size the pool from `--max-concurrent` |
| 29 | `--listen` serving limits | Per request `Limits::web()` (fuel 100 million, 64 MB, 5 s); `--fuel`, `--timeout`, `--memory` override. Per server (W8, constants): headers 10 s, 100, about 64 KB (one large read can reach about 114 KB); body 10 s, then 408; 1,000 connections; idle keep-alive closes at the 10 s header timeout; 100 queued, then 503; 1 s wait for a worker, then 503 | Expose the per-server values as flags |
| 30 | Response headers a handler may set | All except framing headers (`content-length`, `transfer-encoding`, `connection`, `keep-alive`, `upgrade`), which the host drops and sets itself | Reject such a response as 500 instead of dropping the header |
| 31 | MCP tools | `kio_primer` and `kio_check` only; no run tool, since running needs grants and grants are the operator's decision | Add `kio_run` with grants fixed by the server's own command line |
| 32 | What `Incoming.target` carries | `/path?query` from the request, percent-encoding kept; an absolute-form target (`http://h/p`) loses its scheme and authority and the `host` header stands, and fragments are dropped (hyper parses the request line) | Pass the request line verbatim |
| 33 | Size limits on a served program (W13c). Resolved by the compiler (owner, 2026-11-06): the host checks and compiles, so nothing is checked inside the sandbox and no source is copied in per request; open until C5 ships it | `init` runs under `Limits::default()` (1 billion fuel, 10 s), so startup is bounded; a program the host checks but the guest cannot (about 20,000 functions exhaust its 256 MB memory) is a startup error. Each request still copies the source into the guest, so a 5 MB source needs over 100 million fuel per request and answers 500 under `Limits::web()`. The host-side check runs on the main thread, so deep recursion in `lang` can overflow its stack on huge programs (a debug build overflows at 2,000 functions) | Cap total source size at `Server::new` with a clear error, or pass the checked files to `run` by reference; run the host check on a thread with a large stack |
| 34 | Constants (open: owner to decide) | Not added so far: json.kio writes `fn max_depth() -> Int { 64 }`. `const` would be the first top-level value, and kio has "no globals" | `const NAME: Int = 64;` for `Int`, `Bool` and `Str` literals only, inlined at check time, so no global state exists at run time |
| 35 | Str and Bytes headers (C1a) | `[rc][desc][len][cap]` like every object, not `[rc][len]`: `rt_dec`, `rt_unique` and the free worklist need no type argument, and a `List<Str>`'s elements free by the list's descriptor alone. Costs 8 bytes per string | Give Str and Bytes `[rc][len]`, pass the descriptor to `rt_dec`, and carry it per pointer on the worklist |
| 36 | How runtime operations report errors (C3a) | A fallible `rt_*` takes the error site as its last argument and calls `rt_trap(site, a, b)` itself; each has one kind of error. No sentinel, out-parameter or error getter, and no check in generated code | Return a code (0 for success) and have codegen branch to `trap` after each call |
| 37 | How the harness sees live objects (C3a) | The runtime always counts live objects and `run` traps at site `u32::MAX - 1` if any remain; `Compiled::run` turns that into "compiled program leaked N objects". A component cannot export `rt_live` without a caps.wit change, and a `test-heap` build would need a second runtime.wasm. A leak (a codegen bug) therefore fails a run in production too. Fine until C5 (compiled is not yet the default); revisit there: a production leak is harmless, the instance is discarded | Build a second runtime.wasm with a counter only for tests, or export a count through the `compiled` world |
