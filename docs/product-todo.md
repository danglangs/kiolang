# Product tasks: approving AI-written code by its authority

Direction A (maintainer, 2026-11-09): a team lets agents write backend code and approves what the code can touch, not every line. The host enforces it and logs it. Three tasks make that demonstrable; each is pinned as in the other `*-todo.md` files.

```
agent writes app.kio ──> PR ──> kio check --base: authority diff ──> human approves the diff
                                                                    │
operator runs it:  kio run app.kio --http stripe=… --http-header stripe=Authorization:env:KEY
                   (host enforces grants, injects the secret, writes the audit log)
```

- [x] **S1. Secrets as headers the host adds.** The program never holds the key, so it cannot leak it.
  - `--http-header name=Header:SOURCE`, `SOURCE` = `env:VAR` or `file:PATH`, read once at start (missing or empty: refused, with a hint). Repeatable; only on a granted `Http` name.
  - The host adds the header to every request on that grant: `get`, `send`, `send_all`, and redirects (which stay in the origin). A program sending a header of the same name gets `HttpErr::Invalid`. Refused at start on an `http://` origin that is not loopback (the key would cross the network in clear).
  - Never in audit, `--log`, errors or the report: the audit line lists `"injected":["authorization"]`. Under `--listen`, the same for every run.
  - Threat model, documented: an origin that echoes request headers back (as httpbin's `/headers`) hands the key to the program; grant only origins that do not.
  - Done: a local server receives the header on every method and on a redirect; the program's same-name header refused; the value appears in no output (audit, log, stderr, response to the client); `env:` missing and cleartext refusals with hints; kio-web links signs its webhook with an injected `Authorization`. Independent security review.
  - Result: `Origin::inject` holds each header as a `Secret` (`Debug` prints `<redacted>`) and `perform` adds it to every hop; `prepare` refuses a program header of the same name (`invalid`, audited with `injected`); `kio run` reads `env:`/`file:` once and refuses a missing, empty or whitespace-only value, a bad or reserved name, a repeat, an ungranted name, cleartext origins other than a loopback IP literal, a key file that is not a regular file (read at most 8 KB), inside a granted `--dir` or the `--audit`/`--log` file, never printing the value (a bad spec shows only `name=Header`). Audit: `"injected":[..]` on each request sent, ` injects=..` in the grant's target. Tests: host/tests/http_header.rs (4: every method and a redirect hop at a local upstream with a scan of stdout, stderr, audit and log; 21 refusals with hints; `Debug`; `--listen`). kio-web links: `--http-header hook=Authorization:file:..`, its receiver (`hook.py`) refuses a post without it. Reviewed: fixes in (`localhost` over http, a key inside a `--dir`, `injected` only when sent, spec echo, FIFO and unbounded reads).

- [x] **S3. No native code loaded from disk.** A program granted a `Dir` over `kio run`'s compile cache (`~/.cache/kio`, or a parent such as `--dir home=~`) could write an entry under another program's key; a later run, granted nothing, would load it with `Component::deserialize`, which trusts native code. - [x] **D2. `kio run --json`: a result contract for orchestration** (pinned and approved 2026-11-11, #233-#236). `kio run`, `kio check`, `kio check --base` and `kio check --grants` take `--json`: stdout is then exactly one line, one JSON object, newline-terminated, in every outcome including usage errors, keys in alphabetical order; kio writes nothing else to stdout or stderr. Exit codes unchanged.
  - **Flag.** Every argument that is exactly `--json` is removed before the rest are parsed, so it may stand anywhere after the subcommand. A grants file line `--json` is refused as an unknown flag (output form is the caller's choice, not a grant). `--json` with `--listen` is a `usage` error ("`--json` reports one run; `--listen` serves many", hint "drop --json, or drop --listen"); `kio mcp --json` too.
  - **Streams.** kio has no program stdout: a program reaches the outside only through grants, and `--log name=-` writes to stderr. Plain `kio run` prints `main`'s value on stdout and the report, diagnostics and limit messages on stderr; under `--json` all of those go into the object, and stderr carries only `--log name=-` lines.
  - **Object.** Every field is always present, `null` or `[]` when it does not apply, so one dataclass reads all four commands:

    | field | type | value |
    |---|---|---|
    | `ok` | bool | `errors` is empty |
    | `value` | str or null | `run` only: `main`'s value as text (below); `null` for `()`, `Ok(())`, an `Err` and any failed run |
    | `errors` | list of Error | in the order plain output prints them; one entry for every kind but `check` and `grant` (binding), which list every diagnostic |
    | `report` | list of str | the authority report, one line per function, as `kio check` prints it; `[]` when the program does not check |
    | `diff` | object or null | `check --base` only: `{"grants": [str], "funcs": [str], "added": bool}`, the lines `--base --detail` prints (`--detail` is accepted and changes nothing); `null` when either side does not check |
    | `audit` | str or null | the `--audit` path as given; the log appends across runs, so a caller wanting one run's records gives a fresh path |
    | `used` | object or null | `run` only, once the grants bound: `{"fuel": int, "calls": int, "io": int, "peak_memory": int, "ms": float}` (the audit `end` record's counts, plus wall time from binding, to 0.1 ms); `null` before |

    Error: `{"kind": str, "message": str, "hint": str|null, "file": str|null, "line": int|null, "col": int|null}`. `message` and `hint` are the plain output's text split at `\n  hint: `, without the `kio: ` or `error: ` prefix; a limit's "(raise it with --fuel)" becomes the hint. `file` is the root path as given or a module's path beside it (`examples/web.kio`, where plain output prints `web.kio`); `line` and `col` are 1-based, `col` in characters (Unicode scalar values) from the line start; all three `null` for an error without a span.
  - **Kinds and exit codes.**

    | kind | what | exit | span |
    |---|---|---|---|
    | `check` | a checker diagnostic (each side of `--base`) | 1 | yes |
    | `grant` | binding: a missing, extra or wrong-kind grant (also `check --grants`) | 1 | yes |
    | `grant` | startup refusal: `:ro` dir/kv/db the program can write, `:verify` key it can sign with, an HTTP verb not granted or not a method, H28 (writable `--dir` holding the source), a grants file, store, `--audit` or `--log` file in a forbidden place, an `--http-header` or `--hmac` that cannot be applied (a secret unset or unreadable), a `--dir`, store or log that cannot open, a `main` taking `Incoming`/`WsMessage` without `--listen` | 2 | no |
    | `usage` | a malformed command line: unknown command or flag, a bad flag value, a grants file line that is not a flag, an unreadable program or grants file, `--json` with `--listen` or `mcp` | 2 | no |
    | `err` | `main` returned `Err(e)`: `message` is `e` as plain output prints it after `error: ` | 1 | no |
    | `runtime` | a run-time error at a site: index out of bounds, division by zero, `unwrap` of `None`.. | 1 | yes |
    | `fuel` `memory` `timeout` `stack` `calls` `io` | the run hit that limit (including at instantiation) | 1 | no |
    | `denied` | the host stopped the run on a call: a write to a read-only store or database, a call not in the authority report | 1 | no |
    | `internal` | not compiled yet, an internal compiler error, leaked objects, the audit log cannot be written; the engine cannot start (exit 2) | 1 | no |

    A call the host refuses with a value (`IoErr::Denied`, `HttpErr::Denied`) is the program's to handle: it surfaces as whatever `main` does with it, usually `err`, and in the audit log. `check --base` with authority added is `ok: true`, `diff.added: true`, exit 3.
  - **Value.** Text, not typed JSON: the runtime returns `main`'s value already printed (caps.wit `outcome { value: string }`), and D3/D5 hand it to a model or a person. `value` is that text, except: when `main` returns a `Result`, the `Ok` payload alone (no `Ok(..)`); a `Str` payload is the string itself, unquoted, so a program returning `Ok(j.to_json())` gives text the caller parses as JSON directly. Other types keep their printed text (`Str` bare as plain `kio run` prints it, `["a"]`, `Some("x")`, `<2 bytes>`). The host knows `main`'s return type from the checker (`Program::main_ret`), strips `Ok(`..`)` and undoes the runtime's `{:?}` quoting of a nested `Str`. Typed encoding (`Int` → number, `List` → array, struct → object, enum → `{"Variant": payload}`, `Option` → value or null, `Bytes` → hex) is not in D2: it needs a type-directed encoder in lowering or a caps.wit change, pinned only when a pilot asks.
  - **Examples** (one line each on stdout; `report` and `used` shortened).
    - ok (`main` returns `Result<Map<Str, Int>, Str>`): `{"ok":true,"value":"{\"alice\": 3, \"bob\": 1}","errors":[],"report":["main : input read, out write"],"diff":null,"audit":"run.audit","used":{"fuel":94349,"calls":2,"io":5,"peak_memory":1769472,"ms":4.1}}`
    - `main` returned `Err`: `{"ok":false,"value":null,"errors":[{"kind":"err","message":"orders.csv line 3: 2 fields, expected 4","hint":null,"file":null,"line":null,"col":null}],"report":["main : input read"],"diff":null,"audit":null,"used":{..}}`
