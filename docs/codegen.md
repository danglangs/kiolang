# Codegen design (C0)

How a checked kio program becomes Wasm. Approved (2026-11-06): refcounted values copied on write, a runtime library in Rust, Wasm emitted straight from the IR, the host checks and compiles, recursion bounded by `--stack`. **decide** marks what the maintainer chooses. Revised after an adversarial review.

## Pipeline: one core module

```
build:  runtime/ (Rust, no_std + alloc, wit-bindgen glue, cabi_realloc) ─► runtime.wasm (core module)
host:   source ─► check ─► lower ─► ir::Module ─► codegen: parse runtime.wasm, append the
        program's functions, data and type descriptors (no new imports, so no index shifts)
        ─► wit-component wraps the one module ─► precompile ─► InstancePre ─► run
```

Runtime and program share one linear memory and one heap, and Cranelift sees them as one module. Component composition (wasm-compose, wac) is not used: components share no memory. Wizer is no longer needed; static data are data segments.

How it is built (C2a, proven on `40 + 2`):

1. **runtime.wasm is complete.** `runtime` is built for `wasm32-unknown-unknown` (codegen/build.rs) with `wit_bindgen::generate!` for the `compiled` world: the `run` export, the `trap` import, `cabi_realloc` and the `component-type` custom section are in it. No WASI imports. wit-component's `ComponentEncoder` wraps the final module unchanged.
2. **Entry: placeholder bodies, not a table slot.** The runtime exports `kio_main() -> i64` (main's value as a slot) and `kio_main_desc() -> i32` (its descriptor), whose bodies call through a `read_volatile` pointer so LLVM keeps them opaque. Codegen finds them by export name and replaces their bodies: `kio_main` calls `rt_init(table)`, then main. Simpler than a funcref slot, and a direct call.
3. **Appending without shifting.** `wasm_encoder::reencode::Reencode` re-emits the runtime, overriding only the type, function, memory, code and data sections (and the data count) to add after what exists. Imports never change: generated code calls the `rt_trap` export, which keeps the `trap` import in runtime.wasm, so an import is never added. Runtime bodies are copied as raw bytes.
4. **Static data after the heap's start chunk.** The runtime links stack first (1 MiB), then its data; dlmalloc's first chunk is `__heap_base..__heap_end`, which ends at the initial memory size. Codegen puts the program's data (literals and the descriptor table) at that old end and raises the memory's minimum by the pages it needs; dlmalloc grows memory above them, so the heap never overlaps them.
5. **Static data layout (C3a, codegen/src/data.rs).** One data segment: first each distinct string literal once, as a pinned `Str` (`[u32::MAX][3][len][len][bytes]`, padded to 8); then the descriptor table, a `RawTable` (runtime/src/desc.rs) followed by its five arrays, whose address `kio_main` passes to `rt_init`. The table holds a descriptor for every type in the module (locals, returns, every expression's type), each generic instance its own; `Statics::desc(&Ty)` and `Statics::str` return the index or address, adding one if new.
6. **Runtime operations (C3a, runtime/src/abi.rs):** `rt_<op>` per `Builtin` and `Mut`, plus `rt_eq(desc, a, b)`, `rt_concat`, `rt_list_new(desc, cap)` (then `rt_list_push` per element), `rt_map_new`, `rt_list_get`/`rt_bytes_get`/`rt_list_set`/`rt_list_at` (a slot's address, C3c) for indexes. Pointers are `i32`, `Int` and slot values `i64`, `Bool` results `i32`. A result whose descriptor the runtime cannot name (a `List<Str>` from `split`, an `Option<V>` from `get`) takes it as the first argument. Ownership: non-mutating operations borrow every argument and return +1; mutating ones change the unique place in place and consume the value argument. **Errors:** a fallible operation takes the error site as its last argument and calls `rt_trap(site, a, b)` itself, with `a`, `b` the message's values (index and length; the byte; 0, 0 otherwise); it never returns an error, so codegen emits no check.
7. **Leak check.** The runtime always counts live objects (one add per allocation and free; pinned statics are never counted). `run` traps at site `u32::MAX - 1` with the count if any remain after it displays and frees main's value; the host reports "compiled program leaked N objects", and the differential harness counts and fails on it.
8. **Ownership in `FuncGen` (C3b).** `owned` lists the Wasm locals that hold an owned pointer at the current point of the code: parameters, then each `let` once emitted, then hidden locals of operands evaluated so far. A block records `owned.len()` on entry and at its end decs and zeroes what was added; a loop records it too, and `break`/`continue` dec everything above it; `return` decs all of `owned`. Operands of a call, a runtime operation or `==` are each evaluated into a new hidden local and pushed on `owned` if pointers, so an exit inside a later operand releases them; then they are pushed from those locals (consumed by a call; borrowed by the runtime, then decd) and popped from `owned`. `x = e` evaluates `e`, decs `x`, stores; `x += e` on `Str` appends (16). An expression statement's pointer is decd. `run` decs main's value after displaying it.
9. **Lists, maps and places (C3c).** Elements are `i64` slots, converted on the way in and out (`slot_in`, `slot_out`). A list literal is `rt_list_new(desc, n)` held in a hidden local on `owned` while its elements run, then one `rt_list_push` per element. A place write (`xs[i][j] = v`, `+=`, `push`, `insert`, `remove`, `b.push` on any place) evaluates the indexes and arguments as operands, then `walk`s: `rt_unique` on the root local and store back; then per index step `rt_list_at(list, i, site)` (bounds check; returns the slot's address), load the element, `rt_unique`, store it back into the slot, descend. `=`, `+=` and `-=` load and store the last slot through `rt_list_at` (`=` used `rt_list_set` until C3d); `b.push` stores `rt_bytes_push`'s result back into the slot or the root. `for x in xs`: the list in a hidden local on `owned` below the loop's mark (so `break` and `continue` keep it, `return` drops it, the loop's end decs it); its length read once; each pass `rt_list_get` into `x`, decd and zeroed at the pass's end; after a `break`, the scope end decs that pass's `x`.
10. **Structs, enums, `match`, `?` (C3d).** A struct literal or a variant with a payload is `rt_alloc(desc, variant)` held in a hidden local on `owned` while its parts run in source order, each stored into its slot (byte `8 + 8i` in a struct, `16 + 8i` in a variant), which takes it. A payload-free variant (`None`, `E::A`) is a pinned object `[u32::MAX][desc][variant][0]` in the literal area, one per (descriptor, variant) used (`Statics::pinned`). `e.f` loads the slot and incs it; a base that is a local or a field of one is read in place (no inc/dec of the base, as the interpreter's `in_place`), any other base is evaluated and decd after. `match`: the scrutinee in a hidden local on `owned` (so every exit from an arm releases it; the match's end decs it); each arm is a Wasm `block` that the pattern's tests leave with `br_if` on failure: a variant's number (`i32.load` at 8) before its payload's parts, left to right, reloading each part from the scrutinee along its slot path; `Int`/`Bool` by compare, `Str` by `rt_eq` with the literal. Bindings are `rt_inc`'d copies of their parts, on `owned` like `let`s, released and zeroed at the arm's end; the arm's value leaves through `br` to the match's `block`. `x?`: `x` in a hidden local on `owned`; if its variant is `None`/`Err`, the return value is built (the return type's pinned `None`; `x` itself, inc'd, when its type is the return type; else a new `Err` of the return type's descriptor holding an inc'd copy of the error), then `release(0)` and `return`; otherwise the payload is loaded and inc'd and `x` decd. A place step `.f` is the slot at `cur + 8 + 8f`: made unique and stored back like an element; the last step's slot, field or element, takes `=` by store-then-dec-old (`rt_list_set` is no longer used). `main` may return a struct, an enum or an `Option` (`kio_main_desc` is its descriptor); a `Result` waits for C3e.
11. **`main`'s value, `Option` results, `sort` and `pop` (C3e, C3f).** `main` returns any type: `kio_main_desc` is its descriptor and the runtime's `run` displays it through `display::outcome`, which shows a `Result` that is `Err` as its payload alone with `failed` set, as the interpreter path does. A runtime operation whose result is an `Option` (`parse_int`, `m.get`, `strip_prefix`/`strip_suffix`, `find`, `ok`, `err`, `pop`) takes the result's descriptor and its pinned `None` first (`obj::option`), so a `None` result allocates nothing. `contains`, `ok_or`, `unwrap_or` and `m.get` take their argument as a slot. `sort` and `pop` are place mutations: `walk` makes the path unique, then `rt_list_sort(list)` or `rt_list_pop(desc, none, list)`, whose `Some` takes the popped element's reference (no inc), and the `Option` is the expression's value.
12. **`Float` and slices (C10, C11).** A `Float` is an `f64` in Wasm locals, parameters and results, and its bits in a slot (`i64.reinterpret_f64` in, `f64.reinterpret_i64` out; `kio_main` returns the bits). Descriptor 5 is `Float`, after `Bytes`, so each scalar's index is its tag (`List` to `Enum` are tags 6 to 9). Every operator is its Wasm instruction except `%`, which is `rt_float_rem` (Rust's `%`: Wasm has no float remainder). `==` is `f64.eq` on a scalar; `rt_eq` compares `Float` slots as floats, and compares an object with itself part by part (a value holding a NaN is not equal to itself, as in the interpreter). `to_float`, `abs`, `floor`, `ceil`, `sqrt` and `is_nan` (`x != x`), `is_finite` (`|x| < inf`), `is_infinite` (`|x| == inf`) are inline. `round` is `rt_float_round` (on the bits: `core` has no `f64::round`, and Wasm's `f64.nearest` rounds halves to even); `to_str` is `rt_float_to_str` (`core`'s `{}`, as the interpreter's `to_string`); `to_int` and `parse_float` return an `Option` as in 11. `slice` is `rt_str_slice(s, a, b, site, boundary)` or `rt_bytes_slice(v, a, b, site)`. Its out-of-bounds message needs three values, `slice {a}..{b} out of bounds for length {c}`: the runtime's `trap3` first calls `trap` at site `EXTRA` (`u32::MAX - 2`) with the length, which the host keeps for the next message's `{c}` and returns from, then traps at the call's site.
13. **Capabilities (C4).** The host binds grants to `main`'s parameters (host/src/grants.rs, shared with the interpreter path) and passes them in parameter order to `run`, which keeps them alive for the run and records each one's kind (`CapTable` order, which is caps.wit's `grant` order) and component handle. `kio_main` calls `rt_grant(i, kind)` per parameter (an internal error on a mismatch) and passes the handles to `main`; a `Cap` local is that `i32` handle, never counted. `CapCall` calls `rt_cap_<cap>_<method>(result desc, handle, args..)` (runtime/src/caps.rs, hand-written; codegen's `every_capability_method_compiles` covers all 24), which borrows its arguments and returns +1. A `Str`/`Bytes` argument goes to the host as a pointer into its object; `List<Str>` (only `send`, imported directly rather than through wit-bindgen) as a list of pointers into its `Str`s. The runtime defines `cabi_realloc` (replacing wit-bindgen's weak one): during a capability call a byte-aligned allocation (a `string` or `list<u8>` the host lowers) reserves 16 bytes in front, and the wrapper turns it into a `Str`/`Bytes` in place (`obj::adopt`). Errors are built by variant name from the descriptor table; a `send` status or `close` code that is not a `u16` is `Invalid` without a host call. A handle that is not live, or not of the method's resource, traps in the canonical ABI before the host runs.
14. **`fn` values and closures (C9a).** A `fn` value is a pointer to `[rc][desc][table index u32][0][captures..]`, laid out as an enum variant with the table index in the variant's place. Its descriptor is `Desc::Fn { name, slots }` (tag 10, after `Enum`): `name` is what display prints, `<fn f>` (the function's key) or `<closure>`; `slots` are the captures' descriptors, so freeing and `rt_unique` treat it as a record; `rt_eq` on one is an internal error (the checker refuses it). A `fn` type's own descriptor is a `Fn` with no name and no slots: display and freeing read the object's. A function item, or a closure capturing nothing, is a pinned object `[u32::MAX][desc][index][0]` in the literal area, one per function (`Statics::pinned_fn`). A closure is `rt_alloc(desc, index)` with each captured local stored into its slot after an `rt_inc`. The program's table entries follow the runtime's own in table 0 (runtime.wasm has one for Rust's indirect calls, 46 entries today): `Runtime::scan` reads its size as the first entry, and `Append` raises the table's minimum and maximum and adds one active element segment there. Each entry is a **wrapper**, not the function: callers do not know a closure's captures, so every entry of type `fn(P..) -> R` takes `(object i32, P..) -> R`, pushes each capture from the object (+1 each, since the lifted function consumes its parameters) and the parameters, and calls the function directly. A call through a value evaluates the callee and the arguments as operands (`operands`), pushes the callee and the arguments, `i32.load`s the index from the callee, `call_indirect`s with that type (deduplicated with the functions' types), then drops the callee. Recursion through values is bounded by `--stack` like any call (each call is two frames).
15. **Built-ins taking functions (C9b).** `map`, `filter`, `any`, `all`, `and_then` and `map_err` are emitted inline (`with_fn`), with no call from the runtime back into the program: the receiver, then the function value, each evaluated once as operands (an exit while the function value runs releases the receiver); each call goes through the value's table entry as in 14 (`call_through`); then both are dropped. A list built-in loops `i` from 0 to the length read once, passing `rt_list_get(xs, i)` (+1, which the callee consumes): `map` pushes each result into `rt_list_new(desc, len)`; `filter` keeps an element for which the call returns true, `rt_inc`'d again, in `rt_list_new(desc, 0)`; `any`/`all` keep the last result and leave the loop when it is true (`any`) or false (`all`). On `Option`/`Result` an `if` on the variant: the variant the function takes (`Some`; `Ok`, or `Err` for `map_err`) passes its payload +1 and `map`/`map_err` store the result in a new object of the result's descriptor and that variant; the other variant is rebuilt as `?` rebuilds it: the result type's pinned `None`, the receiver itself (+1) when the types are equal, else a new object of the result's descriptor holding the payload +1. Between the operands and the drops only calls run, which return or trap, so nothing else needs releasing; an error inside the function reports the function's own span.
16. **In-place append and inline fast paths (C8b1).** `x += e` on a local `Str`, and `x = x + a + b ..` (concatenations nested to the left, ending in a read of the assigned local), call `rt_str_append(s, part) -> s'` per part: it takes `s`'s reference and borrows the part; if `s`'s count is 1 it appends in place, moving to a buffer at least twice as large when full (amortized O(1)); otherwise (shared, pinned) it makes a new `Str` with room to grow and drops `s`. For `x = x + ..` every part runs first as an operand (the read of `x` +1), then `x`'s own reference is dropped, so the read is the only one left unless a part read `x` too (`x = x + x`: two references, copied) or another local shares it. Uniqueness is the runtime's count, never a codegen inference. `p += e` on a field or element passes the slot's reference after the place's walk. `Str`/`Bytes` buffers are allocated uninitialized; every byte below `len` is written first. `rt_inc`/`rt_dec`/`rt_unique` are inline: load the count; `inc` adds one if it is in `1..2^31`, `dec` subtracts one if in `2..2^31`, `unique` keeps the object if it is 1; anything else calls the runtime unless pinned (`u32::MAX`), so a free, a copy, a pinned object and a test build's use-after-free checks (count 0 or poisoned) stay in the runtime. A `List`'s object holds `ListBody` `[elements][len][cap]` (u32 each, a `Vec<u64>`'s parts, `#[repr(C)]`, offsets asserted for wasm32), not a `Vec`, whose layout Rust does not fix: `len` is an inline load; an index in `0..len` loads the slot (inc'd if a pointer), else `rt_list_get` reports the error; `push` on the unique list stores the slot and `len + 1` when `len < cap`, else calls `rt_list_push`.
17. **Last uses, borrowed operands, fewer runtime calls (C8b2).** Moves (codegen/src/moves.rs): a backward pass per function, in codegen's evaluation order, finds the reads of pointer locals after which nothing reads the local on any path (the function returns, the scope ends, or a plain `x = e` overwrites it first). Such a read hands over the local's reference and zeroes its slot, so the scope's end and every exit (`return`, `break`, `continue`, `?`) drop 0, a no-op; any position may use a moved read, since it yields +1 as a copy does. Branches (`if`, `&&`, `||`, `match` arms) are analysed from the set after them and joined; `x += e` and a place write read `x` after the value; in a loop, every local it mentions and does not declare is live at the end of a pass and at `break`/`continue`, so a local declared outside a loop never moves from inside it (a `break` in a `while` condition is the enclosing loop's, as in codegen). Borrows: an operand of a runtime operation, `==`, an index base, the receiver and function of a built-in taking one, a called `fn` value or a map key that is a read of a pointer local is not evaluated: the operation uses the local itself, with no inc or dec, unless a later operand of the same operation mentions the local (could assign, mutate or move it); `x = x + ..` borrows no part reading `x`, whose reference is dropped before the appends. A local `match` scrutinee and the operand of `?` are read in place: tests and bindings run before any arm. `rt_str_append` copies `b` before dropping `a`, so `a` may be `b` with one reference. Runtime: `Str` equality and order compare 8 bytes at a time (little-endian words, the first differing byte found with `ctz`; Wasm has no byte swap) while 8 are left, then bytes; map keys, `sort`, `==`, list `contains`. `free` looks up an object's descriptor once. `len` of `Str`/`Bytes`, a `Bytes` index in bounds and a `push` of a byte with room are inline, the runtime called for errors and growth.
18. **Size-class free lists (C8b3).** runtime/src/heap.rs wraps dlmalloc as the global allocator: a block of at most 64 bytes and alignment 8 is rounded up to a class of 8, 16, .., 64 bytes, freed onto its class's list (linked through its first word) and taken back from it; anything else goes to dlmalloc. Before calling dlmalloc while the lists hold over 256 KB, and when dlmalloc fails, the lists are handed back (on failure the call is retried once). Since C8b5 fresh small blocks are carved from chunks and only whole chunks go back (20). `obj` calls it directly, not through `alloc::alloc`; a record's slots are zeroed with word stores. `test-heap` builds use dlmalloc alone. Object layouts are unchanged.
19. **Borrowed parameters; borrowed map keys (C8b4).** `moves::borrowed` decides per function which pointer parameters are borrowed: those its body reads only in places where 17 uses a local in place (operands of runtime operations, `==`, `+`, index and field bases, `match` scrutinees, `?`, called `fn` values, receivers and functions of built-ins, map keys, the iterable of `for`) or passes as an argument for another borrowed parameter; a read anywhere else (a `let`, a value returned, an element, an owned argument, a capture) or an assignment or change in place keeps it owned. Optimistic fixpoint over the module: every pointer parameter starts borrowed, so recursion keeps it. The callee neither drops nor moves a borrowed parameter (it is not in `owned`; a last use copies), and `for` over one uses it without a reference of its own. A direct call passes a borrowed argument without a reference: a local, or a field of one, that no later argument mentions is passed in place, and if that read was the local's last use (17) the local is dropped and zeroed after the call; any other argument is held like an operand and dropped after the call. Calls through values keep one convention (arguments owned, the object borrowed): the table wrapper of a function with borrowed parameters drops their arguments after its direct call, and passes a borrowed capture without a new reference. Safety does not rest on the analysis: the callee only copies or borrows a borrowed parameter (parameters are not `mut`; codegen asserts no assignment or place write), and the caller's reference outlives the call. `Map` lookups by `Str` key (`get`, `remove`, `insert` of a present key) compare against a probe `Key` borrowing the `Str`'s bytes (`Key::probe`, a raw pointer in a `ManuallyDrop`): a key is copied only when inserted new.
20. **Less work per operation (C8b5).** *Inline allocation:* a struct, variant or closure of at most 64 bytes is popped from its size class's free list by generated code (`FuncGen::alloc`): load the head at `lists + 4 * class`, store its first word back as the head, write the header (`rc` 1, `desc`) and the word at 8, zero the pointer slots (a part that exits frees the object), add 1 to the live count; an empty list calls `rt_alloc`. Codegen reads the two addresses from the bodies of `rt_heap_lists` and `rt_live_count` (each one `i32.const`, checked) and the size from the table it emits, so the block is the class the runtime frees it into; heap.rs asserts the layout (`free` at offset 0, 4-byte heads, classes 8..64). A test-heap runtime's heads are a static that stays null, so generated code always calls it. *Chunks:* an empty class carves 32 blocks at once from its 64 KB chunk (`CHUNK`-aligned, from dlmalloc as `CHUNK - 8` bytes so consecutive chunks sit back to back), so building a value calls dlmalloc once per chunk and the next allocations are inline pops. A block finds its chunk by masking its address; a hand-back (more than 256 KB freed since the last, or more than it kept; or dlmalloc failing) counts each chunk's listed blocks and returns the chunks whose carved blocks are all listed. *Freeing* reads the descriptor in place and a record's slots without `record_of`'s copy, frees a list's buffer without the `alloc::alloc` call, and frees the first dying child next without the work list. *Map keys:* a `StrKey` carries its first 8 bytes as a big-endian `u64`, compared before the bytes, and `Key::cmp` is inlined into `BTreeMap`'s search.
21. **`HashMap` (C13).** One source, lang/src/hmap.rs, is the interpreter's table and, included by `#[path]`, the runtime's (`obj::HashMap = hmap::HashMap<Key, u64>`: the runtime's `Key`, values as slots). Entries in a `Vec` in insertion order, a hole per removed one until holes pass half (then compacted); a power-of-two index of chains through the entries, a chain past 8 becoming a `BTreeMap` from key to entry. Hash: murmur3's finalizer on an `Int`; FxHash's step over a `Str`'s length and 8-byte words, then the finalizer. Object `[rc][desc][HashMap]`, descriptor `Desc::HashMap { key, value }` (tag 11, last, so no tag moved). The IR reuses `Map`'s `MapNew`, `Builtin`s and `Mut`s (the type tells them apart), so codegen emits the same `rt_map_*` calls; each runtime operation reads the object's descriptor and takes either kind (`coll::kv`). `==` looks each of one side's keys up in the other; display, freeing, copying and `keys` walk the entries in order. No inline paths: word count's profile is the table's own work (lookup 16% self, `get` and `insert` each hashing and searching).
22. **One search for `insert(k, get(k)..)`; larger size classes (C8b6).** A `Map` object is `[rc][desc][MapBody]`: the `BTreeMap`, whose values are `Cell<u64>`, then `last`, the key and value pointers of the entry `map_get` last found (from a shared `get_key_value`). `map_insert` compares its key with `last`'s first (one compare) and on a match replaces the value through the `Cell`; otherwise it clears `last` and searches. `last` is set only by `map_get` and cleared by every insert that misses it and every remove, the only operations that change a map's nodes; a copy (`unique`) starts with none, and it dies with its object. No codegen change and no global state. A `HashMap` remembers too, inside hmap.rs (so the interpreter's does): `last`, the index of the entry `get` found, in a `Cell`; `insert` compares its key with that entry's (bounds-checked, no `unsafe`) before hashing, and otherwise hashes and searches once for both the replace and the append (`insert_with`, which copies a `Str` key only when it is new). `last` is cleared by `remove` and by compaction (which growth does), the operations that move or remove entries; a copy starts without it. The allocator lists blocks up to 512 bytes: classes of 8..64 (popped by generated code, unchanged) and 128..512 in steps of 64 (runtime only), so `BTreeMap` nodes, line `Str`s and list buffers skip dlmalloc. Smaller: `split` at a one-byte separator counts it first (exact 8-byte masks) and sizes the list once; freeing a `List<Str>` frees its dying elements in place; `Option`/`Json`/`Result` payload variants are built without `alloc`'s zeroing and a second descriptor lookup (`obj::variant1`); integers are formatted without `core::fmt` (`text::int_text`).
23. **L11's built-ins (C14).** Runtime exports as other built-ins for `List.slice` (`rt_list_slice`, `trap3` as `Str.slice`), `join`, `to_lowercase`/`to_uppercase` (`alloc`'s, as the interpreter), `sha256` and `ct_eq` on `Str` or `Bytes` (one export each; lang/src/digest.rs included by `#[path]`), `to_hex`; `reverse` and `extend` are place mutations (`extend` returns the object to store back, as `push`). `Int.min`/`max` are a `select`; `Float.min`/`max` are `f64.min`/`f64.max` and two `select`s that return the other operand when one is NaN. `unwrap_or_else` is inline as 15: an `if` on the variant, the payload +1 or the call (on the `Err`'s payload +1). `sort_by_key` is 15's `map` loop into a list of keys, then `rt_list_sort_by_key` on the unique place. `sort_by` drives lang/src/sort.rs's merge sort (one source, `#[path]`): `rt_sort_new(list)` returns a `Box`ed sort; a Wasm loop asks `rt_sort_next` (a question as `a << 32 | b`, -1 when done), calls through the function value on elements `a` and `b` (inline `list_get`, +1, consumed by the call) and passes the result to `rt_sort_answer`; `rt_sort_finish` permutes the list and frees the sort. The runtime never calls the program. The function argument of both sorts is borrowed like a map key.
24. **`|` patterns and `let`-else (C15, L13, L14).** A `Pat::Or` is tested as a chain: each alternative in a `block` that its failed tests leave for the next one; the last alternative's failure is the pattern's. The first alternative that passes sets an `i32` temp to its number and branches past the rest, so the arm body is emitted once. Binding runs an `if` per alternative on that number (every alternative binds the same locals); `test` and `bind` visit `|` patterns in the same order, which pairs each with its temp. `let`-else arrives as an ordinary `match` (lowering puts the rest of the block in the pattern arm).
25. **Free plans (C8b7).** `rt_init` works out a `desc::Plan` for every descriptor and every enum variant (`obj::plans`: the descriptors' plans, then the variants' in table order) and keeps it with the table, which `abi::table()` now hands out by reference rather than rebuilding per call. A plan is 16 bytes: `kind` (a struct, a variant or closure, a wider one, an enum, `Str`/`Bytes`, a list of scalars, of `Str`/`Bytes` or of other pointers, a map or `HashMap` with or without pointer values, a scalar), `mask` (bit `i` set iff slot `i` is a pointer; for an enum, its variant count) and `size` (the object's bytes; for an enum, the index of its first variant's plan). `free` reads one plan per object (an enum's, then its variant's, the variant checked against the count), visits the set bits of the mask, and frees the block by the plan's size; a struct, variant or closure of more than 64 slots (`Wide`) walks its descriptors as before. `dec` frees a pointer-free object (mask 0, or `Str`/`Bytes`) itself, without `free`'s work list. A plan is a function of the table alone, so it trusts nothing new; native test tables have no plans and `free` makes them per call.
26. **Unboxed one-slot enums (C8c1).** `Option`, `Result` and every user enum whose variants carry at most one slot (at most 64 variants; `Json`, `Tree`, payload-free enums) are two Wasm values outside slots: the tag `i32` and the payload as an `i64` slot (0 for a payload-free variant). A local is two Wasm locals, a parameter two parameters, a function returning one returns both (multi-value: `value_sig`, `block_type`, the `fn`-value wrappers); `Shapes` says which types are unboxed, `Rep` how a type is held, `Val` where a value sits. `Some(x)` is `i32.const 1` and `x` as a slot, no allocation; `None` is `(0, 0)`. **Boxing** (`slot_in`, `box_top`) on entry to a slot, a capture, `==` (`rt_eq`), a runtime operation or capability call that takes the value, and `main`'s result: a variant with a payload is allocated inline with the tag from a local (`alloc` with `Tag::Local`; every such variant is 24 bytes) and takes the payload's reference; a payload-free variant is its pinned object, indexed by the tag from the type's table of pinned variants (`Statics::pins`: 16 bytes per variant, zeros for a variant with a payload). A variant written out where a slot is wanted (`xs.push(Some(v))`, `[Tree::Leaf(1)]`) is built as the object directly (`slot_expr`). **Unboxing** (`slot_out`, `unbox`) on a read from a slot: the tag from byte 8, the payload from 16 when the variant has one, +1 on the payload when the value is owned; a boxed result the runtime still returns (a capability call's `Result`, `parse_json`) is unboxed and its object dropped (`unbox_owned_top`). **Ownership:** a payload local holding a pointer is on `owned` like a `let` (`Owned { slot: true }`), and is moved or copied as a pointer local is; when every variant with a payload carries a pointer (`Option<Str>`, `Result<Str, Str>`), a payload-free variant's 0 makes `inc`/`dec` no-ops, so no tag test; when some variant carries a scalar (`Result<Str, Int>`, `Json`), `inc` and `dec` of the payload first test the tag against the pointer variants' mask (`Masks::tested`, `in_mask`: one compare for a single variant). `match` tests the tag local and reads parts from the payload local; `?`, `unwrap_or`, `unwrap_or_else`, `ok_or`, `ok`, `err`, `is_*`, `map`, `and_then`, `map_err` test the tag and copy or move the payload slot, none of them allocating; `?`'s early return is `(0, 0)` or `(1, error)`. **Runtime:** `_u` variants of `rt_map_get`, `rt_list_pop`, `parse_int`, `parse_float`, `find`, `strip_prefix`/`strip_suffix`, `to_int`, `from_hex` (L26, `_u` only) and the `Json` accessors return the tag and leave the payload (owned) in `rt_scratch`'s 8-byte word (its address read from the export's `i32.const` body, as the allocator's), so a hit allocates nothing; the boxed exports stay. `moves.rs` takes the "holds a reference" predicate (`Shapes::owns`), so an `Option<Int>` is never moved or borrowed and an `Option<Str>` parameter is borrowed as a `Str` is.
27. **Unboxed small structs (C8c2).** A struct of at most 4 fields (`MAX_FIELDS`; `Shapes::flat`, `Rep::Fields`, `Val::Fields`) is one Wasm value per field outside slots: a scalar field as its value (`Int` `i64`, `Bool` `i32`, `Float` `f64`; a `()` field has none), any other field as the `i32` pointer its slot would hold, so a `Str`, `List` or `Map` field is an owned pointer local and an `Option`, enum or struct field stays a boxed object in its local (one level; `Shapes::field_rep`). A local is one Wasm local per field, a parameter as many parameters, a function returning one returns them all (multi-value; `Shapes::types`). `s.f` on such a local is `local.get` (`FuncGen::field`: a pointer field +1, or moved out at the local's last use; a boxed enum or struct field unboxed with a reference, `unbox_field`); `s.f = e`, `s.f += e` and `s.f = s.f + e` write the field's local with no `unique` check (`assign_field_local`); `s.xs.push(v)` and `s.inner.x = v` take the field local as the root container (`walk`). A struct literal is its field values pushed in field order, no object (`StructLit`); where a slot is wanted (`[P { .. }]`, `xs.push(P { .. })`, `Some(P { .. })`) the object is built directly (`slot_expr`), and an operand that becomes a slot (a pushed or inserted value, a stored value, an init of a boxed field) is evaluated as one (`operands_slotting`), so `xs.push(p.value)` of a boxed enum field copies the pointer rather than unboxing and boxing. **Boxing** (`box_struct_top`, `store_fields`) on entry to a slot, a capture, `==`, display, `main`'s result and a runtime operation that takes the value; **unboxing** (`unbox_struct_top`, `unbox_struct`) on `slot_out`: each field loaded, pointer fields +1 when owned, the object untouched (dropped by `unbox_owned_top` when it was a temporary). **Ownership:** each pointer field is on `owned` as a `let` would be (`owned_of` gives one `Owned` per pointer field), moved or copied as a pointer local is; `Shapes::owns` is true when any field holds a pointer, so `moves.rs` borrows a struct parameter read only in place and moves one at its last use; the `fn`-value wrappers unbox a captured struct and drop a lent struct argument field by field. A struct inside an enum payload (`Result<Parsed, Str>`) or a slot stays one object: `?` unboxes the payload with a reference per pointer field and drops the object.

**decide 1: compile cost per `kio run`.** Each run compiles runtime plus program with Cranelift (tens of ms). Recommend: Wasmtime's compilation cache keyed by module hash, so an unchanged program is not recompiled. Done in C5 as kio's own cache (host/src/cache.rs, open_questions #75): about 25 ms to compile, 1 ms to load.

## Interface (caps.wit)

**decide 2: a `compiled` world beside today's `guest` world.** C5 removed the `guest` world: the interpreter runs natively in tests only.

```wit
world compiled {
  import kio:caps/fs; import kio:caps/net; import kio:caps/web;   // unchanged
  import trap: func(site: u32, a: s64, b: s64);                   // a runtime error; never returns
  export run: func(grants: list<grant>) -> result<outcome>;       // grants in main's parameter order
}
```

- The host checks grants (missing, duplicate, unknown) before running, from `main`'s parameters. The report is host-side.
- `trap` is a new import: one more host function on the sandbox wall, so it gets a security review (C7). It records `(site, a, b)` and traps; the host formats the message. A call at the runtime's `EXTRA` site returns instead, keeping `a` for the next message ("How it is built" 12).
- `outcome` is the display string and a failed flag, formatted in the runtime from the descriptor table, matching `Program::display` exactly.
- The glue that was in guest/src/lib.rs (removed in C5) moves into the runtime: error enums by `CapTable` order, `send` with a status that is not a u16 is `Err(WebErr::Invalid)`.

## Values

| kio type | Wasm value | Heap object |
|---|---|---|
| `Int` | `i64` | none |
| `Bool` | `i32` | none |
| `Float` | `f64`; its bits in a slot | none |
| `()` | nothing; 0 in a slot | none |
| `Str` | `i32` pointer | `[rc u32][desc u32][len u32][cap u32][bytes]` |
| `Bytes` | `i32` pointer | as `Str`; `cap` lets `push` amortize |
| `List<T>` | `i32` pointer | `[rc][desc][elements u32][len u32][cap u32]`: a `Vec<u64>`'s parts (16) |
| `Map<K, V>` | `i32` pointer | `[rc][desc]` + the runtime's `BTreeMap` (Int keys, or Str keys ordered by bytes) and the last entry `get` found (22) |
| `HashMap<K, V>` | `i32` pointer | `[rc][desc]` + lang/src/hmap.rs's table (21) |
| struct of five or more fields, enum with a variant of two or more slots | `i32` pointer | `[rc][desc][variant][payload]`, 8-byte slots |
| struct of at most 4 fields | one Wasm value per field: a scalar as its value, any other field the `i32` pointer its slot holds (27) | the same object, built on entry to a slot |
| `Option`, `Result`, enum whose variants carry at most one slot | tag `i32` and payload `i64` (a slot; 0 for a payload-free variant), two Wasm values (26) | the same object, built on entry to a slot; a payload-free variant's is pinned |
| `fn` value | `i32` pointer | `[rc][desc][table index][0][captures]`; a function item is pinned |
| capability | `i32` handle | none; never counted |

- **Containers are Rust's own** (`alloc` in `no_std`): `Vec` and `BTreeMap` give the interpreter's exact semantics and costs, including key order.
- **Headers are 8 bytes**, so `i64` slots align.
- **Type descriptors.** Codegen emits a table: per struct and per (enum, variant), which slots are pointers and their descriptors; a container's element, key and value descriptors; names for display (a struct's or enum's module-qualified key, record field names in a `fields` array parallel to `slots`, bare variant names; `Option` and `Result` print variants alone). Objects carry a descriptor index, so `rt_dec`, `rt_unique`, `rt_eq` and display need no type argument.
- **Static objects** (string literals, interned per module; payload-free variants like `None`): refcount `u32::MAX`, pinned. `rt_inc`/`rt_dec` skip them; `rt_unique` treats them as shared and copies.

**decide 3: no unboxing in v1.** `Option<Int>` and small structs stay on the heap. Recommend: correctness first; C8 measures. C8c1 unboxed one-slot enums outside slots (26), C8c2 structs of at most 4 fields (27).

## Ownership

Every expression yields an **owned** reference (+1).

| Position | Rule |
|---|---|
| Reading a local | `rt_inc` (a copy) |
| A fresh result (literal object, concat, call, builtin) | already +1, no inc |
| Consuming: `let`, assignment, argument (of an owned parameter, C8b4), field or element initializer, `return`, `?`'s early exit | takes ownership, no inc |
| Non-consuming: operands of `==`, `+` on `Str`; builtin receiver and arguments; index or field base; the match scrutinee at the match's end; the `for` iterable at loop end | `rt_dec` after use |
| Assignment `x = e` | evaluate `e`, then `rt_dec` the old value, then store |
| A local's scope ends | `rt_dec`, then set the slot to 0; `rt_dec(0)` is a no-op |
| A place write (`xs[i] = v`, `push`, `insert`) | indexes, then the value, then for each container along the place: `rt_unique`, store the result back into its parent, bounds-check, descend |
| `for x in xs` | the loop owns a reference to `xs` in a hidden local, released on every exit; that count is what makes `xs.push` in the body copy |

**Early exits** (`return`, `break`, `continue`, `?` in expression position): before evaluating a subexpression that can exit, owned temporaries are spilled to hidden locals; every exit decs the hidden locals and the locals of each scope it leaves. A trap needs no cleanup: the instance is discarded.

Freeing, equality and display are **iterative** (a worklist), so a value nested 10^6 deep cannot overflow the runtime's stack. `rt_inc`/`rt_dec` fast paths are inlined (load, pinned check, add, store); only a free calls the runtime.

C8b2 elides inc/dec pairs at last uses (moves) and for local operands (borrows), "How it is built" 17; the `for` loop still holds its own reference (a moved iterable gives it the local's) unless it iterates a borrowed parameter. C8b4 borrows parameters a function only reads in place (19).

## Runtime errors

Every error site has a number; the host keeps `site -> (span, message template)` beside the compiled module. Generated code calls `trap(site, a, b)` with run-time values, so `index {i} out of bounds for length {len}` and `byte {n} out of range 0..=255` match the interpreter exactly.

Integer checks emitted explicitly, in the interpreter's order: `/` and `%`: divisor 0 is "division by zero", then `MIN / -1` and `MIN % -1` are "Int overflow" (Wasm's `rem_s` gives 0 and `div_s` traps without a site). `-MIN`, `+`, `-`, `*` check overflow. `+=` and `-=` report the statement's span.

How it is built (C2b): `codegen::Site { span, template }`, one per check; the host's `trap` checks the site is in the table, then replaces `{a}` and `{b}` in the template with `trap`'s arguments. Checks are inline, no runtime call: `+` overflows when `(a ^ r) & (b ^ r) < 0`, `-` when `(a ^ b) & (a ^ r) < 0`; `*` when `a != 0` and `r / a != b`, with `a = -1, b = MIN` tested first (that division would trap). Locals: each IR local with a Wasm value type gets a Wasm local, parameters first; `()` locals get none; hidden locals follow. A hidden local is free again when the expression or statement that took it ends, and is taken again for the same value type (C7a). A limit trap (stack overflow, fuel, timeout) is an `Err` carrying `Stopped` with the limit's message. Function types are deduplicated.

The runtime is built `panic = "abort"` with a panic handler that calls `trap` with an internal-error site, so a runtime bug never looks like a program error. "Host returned a malformed value" becomes unreachable: the canonical ABI enforces types.

## Host calls

The runtime owns `cabi_realloc` and reserves an object header in each allocation, so a returned `string` or `list<u8>` becomes a `Str` or `Bytes` in place, and arguments pass as pointer and length with no copy. Codegen calls runtime wrappers (`rt_cap_dir_read(desc, handle, path) -> ptr`), never raw canonical imports; they are hand-written (item 13).

## Limits

- **Fuel:** Wasmtime fuel. Compiled code spends less per operation; C5 set the defaults to a tenth (open_questions #76). Differential tests compare only runs within both limits.
- **Stack:** `--stack` (decision 6). The runtime's own Rust stack holds only runtime frames, so the guest's 8 MB link setting is gone (C5); linked `--stack-first`, so an overflow faults rather than corrupts.
- **Memory:** `memory.grow` past `--memory` is refused; the allocator calls `trap` with out of memory.

## Testing

```
every program ─┬─► interpreter ─► value, error and span, host calls ─┐
               └─► compiled    ─► value, error and span, host calls ─┴─► equal; live objects 0 unless trapped
```

The runtime is tested natively first (`cargo test`, Miri). Every build counts live objects; test builds also poison freed memory without reusing it. From C2 the differential harness covers lang/tests programs and examples; from C6, generated programs.
